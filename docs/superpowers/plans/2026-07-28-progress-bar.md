# Progress Bar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add ASCII progress bar to cbztojxl showing file-level and image-level progress during CBZ to JXL conversion

**Architecture:** Callback pattern - `create_progress_callback()` creates a closure that updates a single line in the terminal using `\r`. This callback is passed to `convert_jpegs_to_jxl()` and invoked after each image conversion. The `process_cbz()` function coordinates file-level indexing and passes the callback through. The `main()` function controls when progress is shown based on mode flags.

**Tech Stack:** Python 3.6+, standard library only (subprocess, pathlib, etc.)

## Global Constraints

- Progress bar only shown in normal mode (no `-v`, no `--dry-run`)
- Summary line shown in normal and dry run modes (not verbose)
- Progress bar format: `Processing: {filename} [{i}/{n}] |{bar}| {current}/{total}`
- Bar is 20 characters wide using `=` and ` `
- Summary format: `Processing: {filename} - Done! ({count} images)`
- Use `\r` (carriage return) for in-place updates
- Use `end=""` to prevent newline in progress updates

```python
def create_progress_callback(file_name: str, file_index: int, total_files: int, total_images: int):
    """Returns a callback that updates progress display."""
    def callback(current_image: int):
        if total_images <= 0:
            filled = 0
        else:
            filled = int(20 * current_image / total_images)
        bar = '=' * filled + ' ' * (20 - filled)
        print(f"\rProcessing: {file_name} [{file_index}/{total_files}] |{bar}| {current_image}/{total_images}", end="")
    return callback
```
